## Risky

**1. Multi-server routing (transport).** Unchanged from the last review, and
upstream went further: `e26bbe76` (42 call sites in 49 files), `7276f3d0`,
`e664bfb1`, `ee43a764`, `de8a2bc4`, `9f49d05e` all route through
`resolveServerCommand` / `parseServerResourceKey` / `invokeForOptionalServer`.
`1ca1afe1` (SSH tunnel, 4.7k lines) feeds `serverConnectionManager` through
`native-server-connections.ts`, which the fork deleted; its Rust supervisor
(`src-tauri/src/ssh_tunnel/*`) is portable, but a fork version would have to
start the tunnel and then open a connection window at `127.0.0.1:<port>`.
Taking any of them puts a second id form for the same remote session into the
fork — the 1.0.1 failure. **Smaller transport risks:** `35a88c41` sets the
dead-socket timeout to 15 s (3 × 5 s) for native remote windows too, and each
drop there runs `recoverRemoteAfterDrop` (`src/lib/transport.ts:893`), so apply
the short timeout to browsers only. `c5f11722` mounts the offline page without
a web-backend gate, so without Wi-Fi it covers the local desktop app; it also
imports from `reicon`. `8cbcd3f6` (cookie sign-in) deletes the token from
localStorage, but the fork's reconnect (`transport.ts:743-791`) still reads
`jean-http-token`, and the Origin check must accept cloudflared's `Host`; the
fork's `/preview/{root_id}/{sig}` routes (`server.rs:239-240`) need a deliberate
place inside or outside the protected router. `f5b1af20` boxes every native
dispatch onto `spawn_blocking`; re-check the debug build's `RUST_MIN_STACK`
workaround.

**2. UI-state saves erase fork fields.** Unchanged (see 2026-10-18): serde
drops unknown fields on save; `getPinnedCanvasSettings` deletes
`pinned_sessions`. Still do not take those files unchanged.

**3. Session storage.** On-disk data stays compatible in the new range too:
`status_version` (`fee32beb`), `provider_rejected` (`fdaadb18`), `delegated_by`
(`6d5bb4ef`), `collapsed_queued_prompts_sessions` (`f99945c7`) and
`pi_agent_owns_policy` (`6e54bb36`) are all `serde(default)`; session ids are
still `Uuid::new_v4()`. Fork-only fields (`RunEntry.limit_hit`, `pending_fork`,
`pending_move`) are lost only if an upstream-only build writes the file.

**4. Run-state repair (`fee32beb`, `d3ebf7b4`).** `get_run_states` repairs
orphans for any unfinished run the registry does not list. The fork's
`is_session_actively_managed` (`jean-core/src/chat/registry.rs:540`) has no
`ACTIVE_SENDS`, so a run between `start_run` and process registration (no pid
yet) would be marked Crashed by a web reconnect. `ACTIVE_SENDS`/`SendClaim` must
come first. The server-side startup resume also changes who tails PI-host and
Codex runs; check against the fork's PI host tailing and `limit_hit` recovery
(`run_log.rs:2556-2614`). The fork frontend still reads `runningSessions`
(`src/App.tsx:567,690`), which `fee32beb` drops from the init payload. 22 / 10
conflicting files.

**5. Delegation link copied by fork, move and transfer (`6d5bb4ef`).**
`delegated_by` must be cleared in `fork.rs` (next to `started_by_session_id`,
`fork.rs:130,272`), `session_move.rs` and `transfer.rs`, or a forked or moved
session reports back to the original sender. Upstream has none of these files.

**6. Archived data gets purged (`4a1c9994`, 171 files, 118 conflicts).**
Archive is removed; `archived_at` now means "soft-deleted". At startup and then
daily, `cleanup_deleted_items` deletes sessions whose `archived_at` is older
than `DELETED_ITEM_RETENTION_DAYS` (30), whatever the user set, and for
worktrees archived by older code runs `git::remove_worktree` plus
`delete_branch`. It also removes `archive_retention_days`,
`archived_by_base_close`, `include_archived` and `unarchive_session`. The fork
keeps archives forever (`archive_retention_days` forced to 0 on import,
`jean_import.rs:392`), uses `archived_by_base_close` (`fork.rs:133,253`,
`storage.rs:867,981`) and exposes archive/unarchive through MCP
(`dispatch.rs:2646-2660`). A merge would delete users' archived sessions,
worktrees and branches without asking. `065ab383` builds on it. **Never take.**

**7. Per-client UI state (`cdbb6af7`).** Each client saves
`ui-clients/<id>.json`; at startup `ensure_native_ui_client_locked` rewrites
`ui-state.json` with `shared_fields_only()` (upstream
`ui_client_state.rs:245,261`), keeping only `pinned_recent_session_ids` and
`project_canvas_settings`. The fork's stars (`jean-core/src/lib.rs:3153-3161`),
session sort, expansion and mobile tab move into the native client's file, so
web access and phones lose them. `merge_shared_canvas_settings_locked`
replaces the whole canvas map (`:225`), so a stale client overwrites other
clients' project pins and labels (fork `lib.rs:3284-3295`) — Risky 2 again,
across clients. Skip; re-implement only if per-client navigation is wanted.

**8. Preference defaults and project files.** `72b91566` rewrites a saved
`default_execution_mode: "plan"` to `"build"` on every load and saves it back
(`migrate_plan_default_execution_mode`, upstream `lib.rs:704`), and a send with
no mode now falls back to `"build"` where the fork uses `"plan"`
(`jean-core/src/chat/commands.rs:215,240`) — write permission where Plan was
implied. Take `/plan`, `/build` and Shift+Tab without the migration, or skip.
`650ce931` deletes `CLAUDE.md` (580 lines) and needs `claude_host.rs` from
`8e9aaa44`. `3eb5e2f5` (auto-steer off) and `1b815c26` (removed toggles) are
unchanged from the last review.

**9. Release and identity.** Low risk. Upstream touched nothing that sets
Splitkick's identity (product name, `app.splitkick.desktop`, updater feed and
pubkey live in `src-tauri/tauri.fork.conf.json`); the Splitkick version comes
from the overlay (`scripts/splitkick-version.mjs:101-111`, 1.5.0) and must stay
above it. Leaks to watch: the DMG background ("Install Jean") sits in the base
config `bundle.macOS.dmg`, which the overlay does not override, and
`scripts/build-fork-macos.sh:12` builds a DMG; upstream's base CSP lacks the
fork's `frame-src … splitkick-artifact:` and the overlay has no CSP, so never
take upstream's side of `tauri.conf.json` wholesale. `tauri.windows.conf.json`
is unchanged upstream (title "Jean"); the fork's NSIS build applies the overlay
after it (`preflight.yml:168-169`), so Splitkick wins. The only upstream
workflow change is the bun pin in `4aaa8023`.
