## Risky

**1. Multi-server routing (transport).** Upstream keys every remote resource as
`<serverId>:<resourceId>` (`src/lib/server-resource.ts:9-11`), routes through
`resolveServerCommand` (`transport.ts:295-335`) and re-scopes results and events
(`server-command-routing.ts:263+`, `server-connections.ts:218`). The 1.0.1
double-key bug is fixed upstream by `1b3ae14c` (local ids stay raw,
`toRawLocalResourceId` strips old `local:` ids), but the model is still
two-form by design, and `d0d906c8` ([#801](https://github.com/coollabsio/jean/pull/801))
shows the same class of bug coming back (a remote parent id scoped twice). The
fork's per-window design uses raw ids in every window. Taking `c1a3979d`,
`c14a06db`, `e2470935`, `1d6170ed` or `22b18f4e` would put a second id form for
the same remote session into the main window while its connection window keeps
the raw one — the 1.0.1 failure again, across windows. Twelve of these commits
are in the reverted range; `22b18f4e`, `d0d906c8`, `ffb7a2ec`, `23436277`,
`d35dd99d`, `02a8a744`, `319de6ac`, `0e9645ef` are newer.

**2. UI-state saves erase fork fields.** Both sides' `UIState` load the other's
file (no `deny_unknown_fields`, all fields `#[serde(default)]`), but serde drops
unknown fields on save. One save by upstream code removes the fork's stars,
project pins, labels, session sort and expansion state. Worse, `f2a6d9fe` makes
`getCurrentUIState` write `project_canvas_settings: getPinnedCanvasSettings()`
(upstream `useUIStatePersistence.ts:34,272`), which keeps only `pinned_labels`
and so deletes the fork's `pinned_sessions` on every save. `b51d042d` (in the
reverted range) replaced `projectCanvasSettings` from localStorage after
hydration; that matches the "pinned rows switching on and off" seen in 1.0.1.
Do not take `getPinnedCanvasSettings`, the re-apply-on-refetch effect
(upstream `:1153`) or the `client-view-state` files unchanged.

**3. Session storage.** On-disk data stays compatible: new `Session` fields
(`selected_permission_mode`, `pinned_tables`, `hidden_table_checklists`,
`pending_acp_permission_requests`, `review_activity_at`, tool-call `is_error`,
`subagent_usage`, index `unread_summary`) are all `#[serde(default)]`; nothing
is renamed. Two behaviour changes: `701e81f9` makes a session saved without a
mode reopen in **Plan** (`legacy_execution_mode()`, upstream `types.rs:860`),
and a downgrade silently drops the new fields on the next write. Session ids are
still `Uuid::new_v4()`. `8e9aaa44` writes new run-log markers
(`jean_claude_host_start`, `steered_user_message`) that the fork's tailer would
end at the first `result`; only relevant if `claude_auto_steer_enabled` is on.
`982c2bc8` adds `agents/`, `jean-agent/` and `agents.db` to the data dir.

**4. Release and identity.** Low risk. Splitkick's identity (product name,
`app.splitkick.desktop`, updater feed and pubkey, version 1.0.6) lives only in
`src-tauri/tauri.fork.conf.json`, which upstream never touches; upstream changed
nothing under `.github/`. Upstream's version bumps only change the base
`tauri.conf.json`, `package.json` and `Cargo.toml` files, which the fork's
updater does not read. One leak: `e0392ff8` adds `bundle.macOS.dmg` with a
"Drag Jean to Applications" background to the base config; the overlay has no
`dmg` key, so the Splitkick DMG would show it. Never copy the upstream version
into the overlay — the next Splitkick release must stay above 1.0.6.

**5. Preference defaults.** `3eb5e2f5` flips Codex/OpenCode/PI/Grok auto-steer
to off (queue) for new installs and missing fields; the fork defaults to on
(`lib.rs:463-478`). `1b815c26` removes toggles the fork still uses.

## Recommendation

**Do not merge all, and do not merge up to any upstream version.** Every
upstream tag from v1.0.1 on carries the multi-server model and the icon swap,
which replace the fork's remote windows, sidebar and icons and repeat the 1.0.1
failure mode. A full merge conflicts in 184 files.

**Cherry-pick in three batches, each on its own branch:**

1. **Data safety (backend only):** `62ab40f9`, `c3f0b962`, `08653d80`,
   `3e493909`, `03244af4`, `ae0e6321`, `b7a561c8`, server half of `6c5f15fe`.
2. **Backend and chat fixes:** `2fbc3fc7`, `81244d2c`, `9deaade0`, `0c335211`,
   `d6c7285c`, `1c041f2c`, `b740f9c1`, `0efc061d`, `79b67714`, `1f5b1210`,

   `c19ef8bd`, `40d2606f`, terminal/WSL `0c6347f2` `85c49c2b` `8e204e61`
   `c087a014` `a027751e`, models `b63770be` `e0cfdd87`.
3. **Features, one at a time:** `e4668444` (Mermaid), `d2f0e196`
   (auto-continue), `d5317ad8`, `1eb3add5` (Radix). Later, as separate product
   decisions: pinned tables, subagent panel, `8e9aaa44`.

Only batch 1 changes shared persistence, and none of the three batches touches
transport or ids. Keep `last-sync.json` where it is: cherry-picks do not move
the baseline. A cherry-pick conflict count above is against `main` today and
will grow as the fork moves.

Each picked commit was chosen by its subject, area and conflict check. Read
each one with `git show` before picking it, and drop it if it depends on
upstream's routing (`resolveServerCommand`, `serverResourceKey`, `invokeForServer`)
or on reicon icons.

**Test plan per batch:**

- `bun run check:all` and `cargo test` in `jean-core`.
- Batch 1: corrupt `projects.json` by hand and start the app (expect restore
  from `.bak`); kill the app during a running Claude turn, restart (expect the
  session to recover, not stay "running"); confirm file modes of written
  session files are kept; load an existing Splitkick data dir and check stars,
  project pins and labels survive two restarts.
- All batches, per `.ai/lessons.md` "Do not release a large upstream merge on
  green tests alone": run the real desktop app from the branch with the user's
  remote servers enabled, open a remote connection window, let an agent run in a
  pinned session, answer a question, pin/star from the main window and from Web
  Access, and check nothing shows twice or flips.
- Batch 2: one turn each on Claude, Codex, OpenCode, Grok, PI; cancel a Claude
  turn before output and resume.
- Batch 3: Radix — open every context menu with press-drag-release and check no
  item runs by itself; Mermaid — render a diagram and check bundle size.
- `bun run check:branding` before any release.
